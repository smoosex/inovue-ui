Default to using Bun instead of npm/yarn/pnpm.

- Use `bun install` instead of `npm install` or `yarn install` or `pnpm install`
- Use `bun run <script>` instead of `npm run <script>` or `yarn run` or `pnpm run <script>`
- Use `bunx <package> <command>` instead of `npx <package> <command>`

Always use `type` instead of `interface` for type definitions.

Never change `src/lib/utils.ts` and `src/components/ui/**/*` unless the user requests, that is generated by shadcn-vue cli.

Treat `src/components/vue-bits/**/*` as external/shared visual building blocks. Do not modify them unless the user explicitly asks.

Always use Kebab-case for Event Names.

## Rule Files

If `.Codex/rules/` exists in this repo, read and follow the relevant files before making larger changes. Do not assume those files exist.

## Project Positioning

This repo should be treated as a shadcn-vue component workspace and registry source, not a normal feature app.

The user-authored components in this project are the directories under `src/components/` except:

- `src/components/ui/**/*`: generated by shadcn-vue cli
- `src/components/vue-bits/**/*`: shared visual bits, not the main authored registry components

The main deliverables in this repo are:

- component source files in `src/components/**/*` except `ui` and `vue-bits`
- demo views in `src/views/**/*`
- component docs in `docs/**/*`
- generated registry JSON files in `public/r/**/*`

## Commands

```bash
# Run the demo app
bun run dev

# Type-check and build
bun run build

# Generate shadcn-vue registry JSON files into public/r
bunx --bun shadcn-vue@latest build --output
```

## Working Model

When implementing or updating a reusable component:

1. Modify the component source under `src/components/` except `ui` and `vue-bits`
2. Keep the matching component demo in `src/views/` aligned when behavior or API changes
3. Update the related docs file in `docs/` when props, events, slots, or behavior change
4. Regenerate the registry JSON output in `public/r/` when the component output should be published

Do not hand-edit generated files in `public/r/` unless the user explicitly asks for that. Prefer regenerating them with the shadcn-vue build command.

## Directory Guide

```text
src/
├── components/
│   ├── ui/                 # shadcn-vue generated primitives
│   ├── vue-bits/           # shared visual bits
│   └── */                  # authored reusable components for this repo
├── views/                  # component demo pages, mainly for showcasing component usage
├── router/routes/          # demo route registration
└── assets/                 # styles and static assets used by demos/components

docs/                       # component usage docs
public/r/                   # generated registry JSON output
```

## Component Rules

- Reusable behavior belongs in `src/components/*`, not in `src/views/*`
- `src/views/*` mainly exist to demonstrate components, not to hold business logic
- `src/views/*` should show real supported usage of the component API
- If you add or change props, emits, slots, or locale behavior, update demos, docs, and registry output in the same task when appropriate
- Preserve compatibility for published component APIs unless the user explicitly wants a breaking change
- Prefer i18n-aware text for reusable components instead of hardcoded business copy
